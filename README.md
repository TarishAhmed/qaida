# Qaida

An Android app that teaches a complete beginner to read Quranic Arabic in Indo-Pak script, in 90-second sessions.

- Fully offline. The app declares no internet permission; the build fails if any library adds one.
- Free and open source, with no ads, accounts, analytics or tracking.
- Trains hearing before speaking: listening cards are graded, while the learner's own recitation is never scored.

## Status

Early development. The learning engine (scheduler, session composition, listening cards) works, but the real
letter content and audio have not been added yet. Builds published under Releases are **previews built on
placeholder content**: every letter shows ؟ and every clip is silence. They are for testing installs and the
session flow, not for learning, and they install as a separate app (`in.qaida.app.preview`).

## Building

JDK 17 and the Android SDK (API 35) are required.

```sh
./gradlew test assembleDebug          # unit tests and a debug APK on the stub content pack
./gradlew connectedDebugAndroidTest   # end-to-end session test on a connected device or emulator
```

Release builds refuse to package until real content is in `app/src/main/assets/content/`; the debug stub pack
is generated by `tools/gen_stub_pack.py`.

## Content

Real content goes in `app/src/main/assets/` (then delete `app/src/debug/assets/`, the generated stub):

- `content/letters.json`, `content/confusion_sets.json`, `content/makhraj.json`, optional `content/boss.json`
- `audio/<letterId>_<context>_<voiceId>.opus` for contexts `isolated`, `fatha`, `kasra`, `damma`
  (Opus, 24 kbps, mono, 16 kHz, -16 LUFS; up to four voices each)
- optional spoken instructions `audio/instr_<cardtype>_<en|ml>.opus`
- `makhraj/*.svg` diagrams (paths, rects, circles, ellipses, lines, polygons; black or currentColor follows the theme)
- boss lines in the DigitalKhatt IndoPak text encoding, to match the font

`./gradlew test` runs the asset validator over the pack: missing audio, empty confusables or undefined makhraj
fail the build. A release build also fails if the word PLACEHOLDER survives anywhere in release assets.

## Releasing

Bump `versionName`/`versionCode` in `app/build.gradle.kts` (versionCode = MAJOR×10000 + MINOR×100 + PATCH),
then push the matching tag `vMAJOR.MINOR.PATCH`. The release workflow checks the tag against the declared
version, signs with the key held in repository secrets, and publishes: a pre-release preview while the stub
pack is in use, a full release once real content exists. Builds are reproducible; CI builds twice and compares.
